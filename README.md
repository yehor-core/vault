# Vault

A browser-native private-key store on top of IndexedDB. Design: [DESIGN.md](DESIGN.md).

> Status: S5 in progress. Unprotected vault with ed25519 and secp256k1 keys in named scopes: generate, list, sign, delete per scope; wipe for the whole vault. Keys are encrypted at rest in a versioned storage format, records are validated and fail closed, and errors are classified. Keys can carry a label, fixed at generate. Several tabs can use one vault at once: concurrent writes lose no update, first-time setup converges, a stale tab can't undo a wipe, and `vault.onChange` tells every tab that the vault may have changed. Not built yet: passkey keys, passkey protection.

## Setup

Requires Node.js ≥ 24 (developed on 26 LTS).

```sh
npm ci
npx playwright install --with-deps chromium firefox webkit   # --with-deps installs system libraries (sudo)
```

## Browser support

| Engine | Version tested (Playwright 1.64.1) | Unit + e2e suites | Vault (unprotected, ed25519 and secp256k1) | Passkey features |
|---|---|---|---|---|
| Chromium | 156 | ✓ | ✓ | not built yet |
| Firefox | 157 | ✓ | ✓ | not built yet |
| WebKit | 27.2 | ✓ | ✓ | not built yet |

Needs WebCrypto Ed25519, ECDH P-256, HKDF and AES-GCM, IndexedDB and `Uint8Array.prototype.toBase64` (ES2026), in a secure context. secp256k1, and ed25519 verification, run on `@noble/curves` 2.3.0, pinned exactly (DESIGN.md §3.3). WebKit (Playwright, Linux) has four quirks that shape the design; see DESIGN.md §8:
- It loses stored X25519 keys.
- Its point import accepts off-curve points.
- Its Ed25519 key generation fails about 0.7% of the time (Vault retries it).
- Its Ed25519 verify crashes the tab on degenerate public keys, so Vault verifies ed25519 on `@noble/curves` and never calls it.

## Property → test

Test references: `<name> ›` cites `test/unit/<name>.test.ts`, `e2e ›` cites `test/e2e/`; a middle segment names the `describe` group. `npm run check:refs` checks that every cited test exists. Every unit test runs in all three engines. Every test about keys runs once per registered key type, except tests of one type's own behaviour, which name the type. Each row was break-checked: the guarding code was broken once and the test went red in every listed engine. Where two guards protect one property, both were broken together. The type row was broken in `src/scope.ts` and went red in `npm run typecheck`. Exception: breaking the SPKI guard turns its test red only in WebKit, the only engine whose `raw` import accepts off-curve points. Not break-checked: the two platform rows, "Keys persist" and "Opening and listing write nothing", and the "after commit" cut of the closed-tab and crash row, which are functional checks (that cut comes after the write has committed, so a write split in two finishes before the page goes; the "before commit" cut is the one that catches it).
